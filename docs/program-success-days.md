# 程序成功天数与 Telegram 摘要

每个账号分别保存程序连续成功天数、累计成功天数，Telegram 显示完整账号邮箱、积分变化、耗时和完成时间。失败时显示原因和已知积分；统计无法读取或保存时显示“未知”，不会伪装成 0 或删除原记录。

这两项统计来自程序任务结果，不读取微软签到连续天数：

- 按北京时间的自然日，每个账号一天最多计一次成功。
- 账号任务完整返回成功才计数，失败、部分完成或缺失的工作进程结果不计成功。
- 失败或漏跑一天后，下一次成功从连续 1 天开始，累计成功天数保留。
- 同一天先失败后成功计一次；已经成功后再失败不撤销当天成功。
- 跨零点完成的任务归属于启动时领取的执行日期，与每日防重复标记一致。
- 多个账号分别统计；家庭和云端各自保存记录，不相互同步。

记录保存在持久化配置目录 `config/run-history.json`，更新或重建容器时必须保留这个文件。记录使用文件锁和原子替换保存。账号邮箱在记录中转为小写用于匹配，在通知中保留配置的完整邮箱。

首次升级可执行：

```bash
docker compose exec -T microsoft-rewards-script npm run run-history:init
docker compose exec -T microsoft-rewards-script npm run run-history:status
```

华为云命令需追加 `-f compose.yaml -f compose.huawei.yaml`。初始化不会运行 Rewards，不重置每日限制或安全熔断。只有单账号部署的最后一条已确认成功记录可作为 1 天起点；缺失的更早历史不推算，多账号旧全局结果不归属到具体账号。初始化已存在的统计文件不会重复补录。

可通过 `.env` 中 `CONFIG_TELEGRAM_SOURCE_LABEL=家里软路由` 添加来源名称。云端 Worker 已添加“北京华为云”，云端无需重复配置名称。Worker 与直连 Telegram 共用相同的账号摘要格式。
